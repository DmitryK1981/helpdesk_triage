# Сценарий демо-видео (2–3 минуты)

Задача видео — доказать: запрос → ответ → запись в БД, плюс показать надёжность
(fallback, лимит). Снимать с экрана, с голосовым комментарием или субтитрами.

## Подготовка перед записью

```bash
cd helpdesk
venv\Scripts\activate          # или source venv/Scripts/activate
uvicorn app.main:app --reload
```
Открыть в браузере: `http://127.0.0.1:8000/`

## Тайминг

**0:00–0:20 — Контекст (10–15 сек на титульный план + переход в браузер)**
Коротко голосом: «Это MVP-сервис триажа обращений: принимает текст, классифицирует
через LLM, готовит черновик ответа и пишет историю в SQLite».

**0:20–0:50 — Happy path: запрос → ответ**
На вкладке «Новое обращение» вставить текст из `demo/sample_tickets.txt`
(лучше однозначный, например из блока BILLING — сразу понятная категория).
Нажать «Отправить». Показать результат: категория, уверенность, эскалация,
черновик ответа. Прокомментировать: «ответ сгенерирован реальной моделью
gpt-4.1-mini через proxyapi.ru, temperature=0.2».

**0:50–1:10 — Запись в БД**
Переключиться на вкладку «История и аудит». Показать, что новая строка
появилась вверху таблицы, с теми же category/confidence/escalate.
Кликнуть по строке — открыть детальную панель, показать полный текст и
черновик ответа. Это и есть «история → аудит» из задания.

**1:10–1:35 — Сценарий "всё сломалось"**
Либо: отправить обращение из блока «неоднозначные» в sample_tickets.txt
(например «Не работает.») и показать, что при низкой уверенности сервис
сам ставит escalate=true. Либо (более наглядно) — показать запись в таблице
с заполненным полем «ошибка» (⚠) и открыть её детали, где виден текст
реальной ошибки LLM и шаблонный ответ «передано оператору». Прокомментировать:
«если модель упала или вернула не-JSON — сервис не падает, а эскалирует».

**1:35–2:00 — Лимитирование**
Переключиться в терминал. Показать `scripts/collect_log.py` или быстрый
curl-цикл с одним client_id — 5 запросов проходят (200), 6-й получает 429.
(Можно заранее записать терминал отдельным дублем и склеить.)

**2:00–2:20 — Валидация**
Один быстрый пример: пустой текст или текст > 2000 символов → 422.
Можно показать через `/docs` (Swagger UI) — там видно схему и ошибку.

**2:20–2:40 — Итог**
Показать вкладку «История» с накопленной статистикой (стат-плашки:
всего обращений, % эскалаций, ошибки LLM, график по категориям).
Сказать: «вся история — в SQLite, лог из 60 реальных откликов — в
demo/responses_log.txt».

## Чек-лист перед публикацией видео

- [ ] Видно адресную строку браузера (127.0.0.1:8000 — честно, без подмены)
- [ ] Показан хотя бы один happy path целиком (запрос → ответ → запись в БД)
- [ ] Показан хотя бы один сбойный/граничный сценарий (fallback, 422 или 429)
- [ ] Не длиннее 3 минут
- [ ] Нигде на экране не виден реальный LLM-ключ (терминал/.env не показывать)
